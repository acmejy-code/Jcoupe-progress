# JCOUP 관리자 v3.2.1 — 수행평가 입장/시작 SDK 사전읽기 완전 제거

이번 핫픽스는 v3.2.0의 REST 직접 반영 앞에 남아 있던 Firestore SDK `getDoc()` 사전 읽기를 제거합니다. 학생 입장 열기·시험시간 저장·시험 시작은 관리자 화면이 이미 보유한 서버 스냅샷을 사용하고, 실제 상태 변경은 REST commit으로 직접 처리합니다. 이전 평가의 SDK pending-write/network queue가 새 평가의 입장/시작을 붙잡지 않도록 한 수정입니다.

# JCOUP 관리자 v3.2.1 — 수행평가 생명주기 서버 직접 반영 안정화

## 핵심 변경
- 학생 입장 열기 / 시험 시작 / 평가 종료 / 평가 삭제를 Firestore JS SDK의 로컬 쓰기 큐와 분리했습니다.
- 위 핵심 작업은 Firebase 인증 토큰을 사용한 Firestore REST `documents:commit` 경로를 우선 사용합니다.
- 이전 평가의 지연된 SDK 쓰기가 남아 있어도 다른 평가의 입장·시작·종료·삭제가 그 큐 뒤에서 기다리지 않습니다.
- REST 경로 실패 시에만 Firestore SDK 네트워크를 재초기화하고 새 batch로 한 번 재시도합니다.
- 서버 commit 성공 후 관리자 화면 상태도 즉시 갱신합니다. 새로고침 전 화면만 바뀌는 가짜 성공을 만들지 않습니다.
- 시험 시작 시 시험시간 저장도 동일한 독립 서버 경로를 사용합니다.
- 평가별 ID 독립 운영, 반별 평가 필터링, 평가 목록 접기 기능은 그대로 유지합니다.
- 학생 포털은 v1.6.8 그대로 사용합니다.
- firestore.rules 변경 없음.

## 이번 문제와의 관계
v3.1.2에서 `평가 종료 서버 응답이 8초를 초과했습니다`가 발생한 것은 브라우저의 Firestore SDK write queue가 서버 승인을 받지 못하고 대기한 상태임을 뜻합니다. v3.2.1은 수행평가 생명주기 쓰기를 해당 queue에서 분리해 동일한 평가 또는 다른 반 평가가 연쇄적으로 막히는 것을 방지합니다.

## 배포
관리자 저장소(Jcoupe-progress)의 파일을 이 폴더 내용으로 전체 교체한 뒤 GitHub Pages 배포 완료를 확인하고 Ctrl+F5 하세요. 화면 버전은 v3.2.1이어야 합니다.
학생 저장소는 v1.6.8을 그대로 유지해도 됩니다.
