# 제이쿱 수업 통합 제어 시스템 v2.3.0

v2.2.1의 수업 진도·달력·공통 자료실을 모두 유지하면서 **수행평가 응시 관리**를 추가한 전체 배포본입니다.

## v2.3.0 핵심 기능

- 수행평가 생성: 제목, 학생 안내, 응시 안내, 교실 공통 `응시코드`, 대상 반, 문항 등록
- 평가 상태: `준비(DRAFT) → 응시 중(OPEN) → 종료(CLOSED)`
- 학생 명단: 반별 `학번 + 이름` 일괄 붙여넣기
- 좌석 초기 배치: **학번 오름차순**
- 좌석 실제 배열 맞춤: 학생 카드를 드래그해 순서를 바꾸고 저장
- 관리자 실시간 좌석 감독: 미접속 / 응시중 / 제출완료 / 연결이상
- 학생 상태 변경은 Firestore 실시간 리스너로 즉시 반영
- 관리자 화면은 10초마다 접속 경과 시간을 다시 계산
- 학생 브라우저 heartbeat는 30초 간격
- 응답 CSV 다운로드
- 시험 전 시뮬레이션용 응시 기록 초기화

## 학생 인증 방식

학생 포털 자체는 공개 링크로 접속합니다. 수행평가 입장 시에만 아래 세 가지를 확인합니다.

1. 학번
2. 이름
3. 교실 공통 응시코드

학생별 개인 인증번호는 사용하지 않습니다. 이름·학번은 관리자에 등록된 비공개 학생 명단과 Firestore Rules에서 대조합니다.

## 중요: Firebase 설정 1회 추가

학생 포털의 인증 세션을 위해 Firebase Console에서 **Authentication → Sign-in method → Anonymous(익명)** 로그인을 활성화해야 합니다.

그리고 이 배포본의 `firestore.rules`를 Firebase Firestore Rules에 전체 적용하십시오.

- 응시코드는 `users/{교사UID}/.../assessments`의 비공개 원본에만 저장됩니다.
- 학생용 공개 수행평가 문서에는 응시코드를 저장하지 않습니다.
- 문항 본문은 응시코드 검증을 통과해 세션 문서가 생성된 학생만 읽을 수 있습니다.
- 학생 답안은 본인의 검증된 세션에 해당하는 학번 문서만 읽고 쓸 수 있습니다.

## 배포

기존 `Jcoupe-progress` 저장소의 파일을 이 배포본으로 전체 교체합니다.

1. 전체 파일 덮어쓰기
2. GitHub Desktop Commit
3. Push origin
4. GitHub Actions 초록색 완료 확인
5. Firebase에서 새 `firestore.rules` 적용
6. 관리자 페이지 `Ctrl + F5`

학생 포털은 `Jcoupe-class-portal v1.3.0`과 함께 배포해야 수행평가 기능을 사용할 수 있습니다.
