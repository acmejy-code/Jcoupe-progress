# JCOUP 관리자 v3.1.2 — 수행평가 상태 서버승인 단순화 + 무한대기 차단

v3.1.1에서 평가 종료/삭제 후 추가 `getDocFromServer` 재확인 단계가 네트워크 상태에 따라 오래 대기하면서 버튼이 `즉시 종료 중…`에 고정될 수 있던 문제를 수정한 핫픽스입니다.

## 핵심 변경
- Firestore `writeBatch.commit()` 성공을 서버 반영의 기준으로 사용합니다. commit은 백엔드가 쓰기를 승인해야 완료되므로, 성공 뒤 동일 문서를 다시 서버 조회하지 않습니다.
- 평가 종료/입장 열기/시험 시작/평가 삭제의 핵심 쓰기에 8초 응답 제한을 둬 버튼이 무기한 `처리 중…`에 머무르지 않게 했습니다.
- 수행평가 목록은 `fromCache` 또는 pending-write 스냅샷을 화면에 반영하지 않고 서버 스냅샷만 사용합니다. 새로고침 직후 오래된 OPEN/삭제 전 상태가 다시 그려지는 현상을 차단합니다.
- 평가 삭제는 private/public/content 상위 문서를 먼저 서버에서 삭제 확정하고, attempts/sessions 하위 기록은 백그라운드에서 정리합니다. 하위 정리 지연이 평가 목록이나 학생 입장을 되살리지 않습니다.
- 평가 ID별 독립 운영, 반별 분리, 평가 목록 접기 기능은 그대로 유지합니다.

## 중요
- 8초 안에 서버 승인이 오지 않으면 실패 메시지를 띄우고 버튼을 복구합니다. 네트워크가 늦게 회복되면 이전 요청이 뒤늦게 반영될 수 있으므로 같은 버튼을 연속 클릭하지 말고 목록 상태를 먼저 확인합니다.
- Firestore Rules 변경 없음.
- 학생 포털은 v1.6.8 그대로 사용합니다.
