JCOUP 수행평가2 · Google Drive 추가자료 연동 배포 안내
관리자 v3.5.1 / 학생 포털 v1.8.1 / GAS Drive Bridge v1.0.0

============================================================
1. 이번 변경 핵심
============================================================
기존 v3.5.0 / v1.8.0의 수행평가2 2단계형 기능은 유지하면서
학생 추가자료 PDF 저장소만 Firebase Storage → 교사 Google Drive로 변경했습니다.

- Firebase 프로젝트는 Spark 무료 요금제 그대로 사용
- Firebase Storage 사용/Blaze 전환 불필요
- 학생 PDF는 교사 계정 Google Drive에 비공개 저장
- Firestore에는 파일 자체가 아니라 Drive fileId와 파일명·용량·업로드시각 등 메타데이터만 저장
- 학생이 Drive 공유링크를 받지 않음
- 파일 보기/업로드/삭제는 Google Apps Script Web App을 통해 처리
- GAS가 Firebase ID Token + 기존 Firestore 세션/학급단계/학생기록을 다시 확인한 뒤 작업
- 3차시 시작 이후 학생 업로드·교체·삭제 차단
- 3차시 PDF는 PDF.js canvas 방식으로 렌더링하여 PDF 내부 링크/주석 클릭 비활성화

기존 수행평가1 시험형, Anonymous Auth, 좌석감독, 자동저장, heartbeat 등은 그대로 유지합니다.

============================================================
2. Google Drive 저장 구조
============================================================
GAS 웹 앱을 배포한 Google 계정의 내 Drive에 처음 업로드할 때 자동 생성됩니다.

JCOUP_수행평가2_추가자료
└─ [수업 프로젝트 ID]
   └─ [수행평가 ID]
      └─ A반
         └─ 20501_홍길동
            └─ 20501_홍길동_원본파일명.pdf

파일은 '링크가 있는 모든 사용자'로 공개하지 않습니다.
교사 계정 소유의 비공개 파일로 유지됩니다.

============================================================
3. 먼저 GAS Drive Bridge 배포
============================================================
1) 반드시 PDF를 저장할 교사 Google 계정으로 https://script.google.com 접속
2) [새 프로젝트] 생성
3) 기본 Code.gs 내용을 모두 삭제
4) 배포 패키지의 gas-drive-bridge/Code.gs 전체를 붙여넣기
5) 저장
6) [배포] → [새 배포]
7) 유형: 웹 앱
8) 실행 사용자: 나
9) 액세스 권한: 모든 사용자(학교 계정 정책에서 허용되는 항목)
10) 배포 후 Google 권한 요청 승인
11) 발급된 URL 중 끝이 /exec 인 웹 앱 URL 복사

※ appsscript.json은 선택 사항입니다. Code.gs만으로도 필요한 Drive/UrlFetch 권한은 배포 시 요청됩니다.
※ 웹 앱 URL을 브라우저에서 열었을 때 'JCOUP Drive Bridge / 웹 앱이 정상적으로 실행 중입니다.'가 표시되면 정상입니다.

============================================================
4. 관리자 코드 설정
============================================================
관리자 ZIP을 풀고 다음 파일을 엽니다.

js/drive-bridge-config.js

아래 값을 방금 복사한 /exec URL로 바꿉니다.

webAppUrl: "PASTE_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE"

예)
webAppUrl: "https://script.google.com/macros/s/AKfycbxxxxxxxx/exec"

그 후 관리자 GitHub 저장소 Jcoupe-progress의 파일을 v3.5.1 전체교체본으로 교체합니다.

============================================================
5. 학생 포털 코드 설정
============================================================
학생 ZIP을 풀고 다음 파일을 엽니다.

js/drive-bridge-config.js

관리자와 똑같은 /exec URL을 입력합니다.
그 후 학생 GitHub 저장소 Jcoupe-class-portal의 파일을 v1.8.1 전체교체본으로 교체합니다.

학생 포털 assets/추가자료_등록서식.docx도 함께 업로드해야 합니다.

6. Firebase Console
============================================================
Firebase Storage는 사용하지 않습니다.
Storage 메뉴에서 프로젝트 업그레이드를 누를 필요가 없습니다.

필수:
- Authentication → Anonymous 로그인 유지
- Firestore Database → Rules → 관리자 패키지의 firestore.rules 게시

불필요:
- Storage 생성
- Storage Rules 게시
- Blaze 요금제 전환

7. 실제 동작
============================================================
[2차시]
학생 인증 → 지문/논제 선택 → 사고과정 작성 → 최종 제출

[추가자료 등록]
교사가 해당 반 [2차시 종료 · 자료등록 열기]
→ 학생이 PDF 선택
→ 학생 브라우저가 Firebase ID Token과 PDF를 GAS로 전송
→ GAS가 현재 학생/세션/학급 단계/2차시 제출 여부 재확인
→ 교사 Drive에 PDF 저장
→ GAS가 Firestore extraMaterials 메타데이터 갱신
→ 학생 화면에 등록 완료 표시

[교체]
새 PDF 저장 → Firestore 메타데이터 갱신 성공 → 이전 Drive 파일 휴지통 이동

[삭제]
Firestore 목록에서 먼저 제거 → Drive 원본 휴지통 이동

[3차시]
교사가 [3차시 시작 · 자료 잠금]
→ 학생의 MATERIAL_WINDOW 세션이 더 이상 유효하지 않으므로 새 업로드/교체/삭제 불가
→ PHASE3_OPEN으로 다시 인증한 학생은 자신의 등록 PDF를 읽기 전용으로 열람 가능

============================================================
8. 보안 구조
============================================================
GAS URL 자체는 비밀값으로 취급하지 않습니다.
실제 권한은 Firebase 인증으로 확인합니다.

학생 작업 때 GAS가 확인하는 항목:
- Firebase ID Token 유효 여부(Firestore REST 요청으로 실제 인증 검증)
- 현재 uid의 session 존재 여부
- session의 studentId / className / purpose
- 현재 반 classStages 단계
- 본인 attempt의 authUid / className
- phase2Status == SUBMITTED
- 업로드/삭제는 MATERIAL_WINDOW에서만 허용
- 열람은 MATERIAL_WINDOW / PHASE3_OPEN에서만 허용
- 해당 materialId가 본인의 extraMaterials에 실제 등록되어 있는지 확인

관리자 PDF 열람:
- Firebase Google 로그인 uid가 publicCourses/{courseId}.ownerUid와 같은지 확인

Drive 파일에는 관리용 설명 메타데이터를 기록하여
다른 학생 파일 ID를 임의로 넘겨도 project / assessment / student / material 정보가 일치하지 않으면 거부합니다.

============================================================
9. 파일 제한
============================================================
- PDF만 허용
- 파일 헤더가 실제 %PDF-인지 GAS에서 재검사
- 기본 학생당 최대 3개
- 기본 파일당 최대 5MB
- 평가 설정값(extraMaterialMaxFiles / extraMaterialMaxBytes)을 서버에서도 재확인
- 절대 상한 15MB

10. 정식 운영 전 스모크 테스트
============================================================
테스트 학생 1명으로 아래 순서 전체를 1회 확인하세요.

1) 관리자에서 해당 반 2차시 시작
2) 학생 2차시 작성/제출
3) 관리자에서 자료등록 열기
4) 학생 PDF 1개 등록
5) Google Drive에 JCOUP_수행평가2_추가자료 폴더와 학생 PDF 생성 확인
6) 학생 [보기] 확인
7) 학생 [교체] → 이전 파일이 Drive 휴지통으로 이동하는지 확인
8) 학생 [삭제] → 화면 목록에서 사라지는지 확인
9) 다시 PDF 등록
10) 관리자 수행평가 화면에서 학생 PDF 클릭하여 열람 확인
11) 관리자 [3차시 시작 · 자료 잠금]
12) 학생 추가/교체/삭제 불가 확인
13) 학생 3차시 입장 후 등록 PDF 읽기 확인
14) 최종 입론서 제출
